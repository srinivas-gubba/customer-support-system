# Role: Senior Python Backend Engineer & Agentic AI Architect

Act as a Senior Python Backend Engineer and Agentic AI Architect. Your responsibility is to design and implement a **production-grade, API-driven Agentic Customer Support System using Python FastAPI**.

## 1. Project Context

I am building an Agentic Customer Support Application with two primary prerequisites:

1. **Knowledge Base:** Contains product documentation, FAQs, policies, return policies, refund policies, shipping information, and other customer support-related information.
2. **Database:** Contains transactional customer information, including customer profiles, orders, order items, order status, payment information, shipping details, and refund records.

The objective is to build an agentic system that intelligently determines whether a user's question requires information from the Knowledge Base, the Database, or both.

The agent must never directly access the database. Instead, it must interact with the database through well-defined, secure REST APIs exposed as tools.

## 2. Architecture: Two Categories of APIs

I want to build two distinct categories of APIs.

### Category 1: Tool APIs (Backend Business APIs)

These APIs act as tools that the AI agent can invoke whenever it needs transactional or customer-specific information.

Build independent REST endpoints using FastAPI for database operations.

**A. Customer APIs**
- GET `/api/v1/customers/{customer_id}` – Retrieve customer details.
- GET `/api/v1/customers/{customer_id}/orders` – Retrieve all orders associated with a customer.
- GET `/api/v1/customers/{customer_id}/addresses` – Retrieve saved customer addresses.

**B. Order APIs**
- GET `/api/v1/orders/{order_id}` – Retrieve complete order details.
- GET `/api/v1/orders/{order_id}/status` – Retrieve current order status.
- GET `/api/v1/orders/{order_id}/tracking` – Retrieve shipment and tracking information.
- GET `/api/v1/orders/{order_id}/items` – Retrieve order items.
- GET `/api/v1/orders/{order_id}/payment` – Retrieve payment information.
- GET `/api/v1/orders/{order_id}/history` – Retrieve order status history.

**C. Refund and Return APIs**
- GET `/api/v1/orders/{order_id}/refund-eligibility` – Determine whether an order is eligible for a refund.
- GET `/api/v1/orders/{order_id}/return-eligibility` – Determine whether an order is eligible for a return.
- GET `/api/v1/orders/{order_id}/refunds` – Retrieve existing refund records.
- GET `/api/v1/orders/{order_id}/returns` – Retrieve return records.

Important business requirement:

Do not assume that every customer asking about a refund or return should immediately trigger a refund operation.

For example, if a customer asks, "Can I get a refund for my order?", the agent should:
1. Identify the relevant order.
2. Retrieve order details.
3. Check the refund policy from the Knowledge Base.
4. Invoke the refund eligibility API.
5. Evaluate the response.
6. Explain whether the order is eligible and why.

The agent should only initiate an actual refund or return when the customer explicitly requests the action and all required validations and authorization checks have passed.

**D. Additional Business APIs**

Identify other useful APIs based on typical customer support requirements, such as:
- Customer account information.
- Product information.
- Payment status.
- Invoice retrieval.
- Shipping and delivery estimates.
- Cancellation eligibility.
- Order cancellation.
- Support ticket creation and retrieval.

For operations that modify data, implement appropriate POST, PUT, or PATCH endpoints rather than using GET requests.

### Category 2: Agentic APIs (Agent Orchestration Layer)

These APIs act as the bridge between the frontend/user and the underlying AI agents.

The frontend should never directly invoke individual tools or interact with the database.

Build the following endpoints:

**A. Chat API**
- POST `/api/v1/agent/chat`

Accept a user question and trigger the customer support agent.

Example request:

```json
{
  "customer_id": "CUST1001",
  "session_id": "SESSION1001",
  "message": "Where is my latest order?"
}
```

Expected responsibilities:
- Accept and validate the user's question.
- Identify the customer and session.
- Trigger the agent workflow.
- Allow the agent to determine which tools are required.
- Execute the appropriate tool APIs.
- Retrieve Knowledge Base information when necessary.
- Generate a contextual response.
- Return the final answer along with relevant metadata.

**B. Agent Execution and Observability APIs**

Build additional endpoints to expose the agent's execution details.

- GET `/api/v1/agent/sessions/{session_id}` – Retrieve session information.
- GET `/api/v1/agent/sessions/{session_id}/messages` – Retrieve conversation history.
- GET `/api/v1/agent/sessions/{session_id}/traces` – Retrieve agent execution traces.
- GET `/api/v1/agent/runs/{run_id}` – Retrieve execution status and metadata.
- GET `/api/v1/agent/runs/{run_id}/steps` – Retrieve individual agent execution steps.
- GET `/api/v1/agent/runs/{run_id}/tools` – Retrieve tools invoked during execution.
- GET `/api/v1/agent/health` – Check agent and dependency health.

The execution trace should provide visibility into:
- User's original question.
- Intent identified by the agent.
- Agent reasoning summaries or execution decisions.
- Knowledge Base retrieval operations.
- Tools selected and invoked.
- Tool request and response metadata.
- Validation results.
- Final response generated by the agent.
- Execution duration and errors, if any.

Do not expose internal chain-of-thought, hidden reasoning, credentials, or sensitive customer information through these endpoints. Expose structured execution events, decisions, and audit metadata instead.

## 5. Production-Grade Engineering Standards

Ensure the implementation follows these principles:

1. Separation of concerns between routers, services, repositories, and agents.
2. Routers should only handle HTTP requests, validation, and responses.
3. Business logic must reside in service layers.
4. Database queries must reside in repository layers.
5. The agent must interact with backend functionality through clearly defined tools.
6. Use Pydantic request and response schemas.
7. Implement consistent HTTP status codes and error response structures.
8. Add pagination, filtering, and sorting wherever applicable.
9. Implement authentication and authorization.
10. Validate customer ownership before exposing order or payment information.
11. Protect sensitive information through appropriate response filtering.
12. Implement request correlation IDs and structured logs.
13. Add timeouts, retries, and circuit-breaker strategies for external dependencies where appropriate.
14. Support idempotency for operations such as refunds and cancellations.
15. Implement audit logging for all sensitive and transactional operations.
16. Keep GET endpoints strictly read-only.
17. Never expose database credentials or internal implementation details to agents.
18. Add rate limiting and input validation.
19. Design the APIs to support horizontal scalability.
20. Implement safe error handling without leaking internal exceptions.

## 6. Agent Tool Integration

One of the most important requirements is that the backend APIs must be easily consumable as tools by the agent.

Design each tool with:
- A clear tool name.
- A meaningful description.
- Explicit input parameters.
- Typed input and output schemas.
- Well-defined error responses.
- Business validation.
- Appropriate authorization checks.

The agent should dynamically select the appropriate tools based on the customer's question.

Examples:

| Customer question | Expected tool selection |
|---|---|
| Where is my order? | Get customer orders → Get order tracking |
| What is my order status? | Get order details/status |
| Can I return my order? | Get order details → Check return eligibility |
| I want a refund. | Get order details → Check refund eligibility → Request confirmation → Initiate refund |
| What is your refund policy? | Knowledge Base retrieval |
| Why was my refund rejected? | Get refund records → Retrieve refund policy |
| What products do you sell? | Knowledge Base or Product API |
| I received the wrong item. | Get order details → Get order items → Create support ticket |

Do not hardcode a single tool sequence for every question. The agent should select tools based on intent, available context, and business rules.
